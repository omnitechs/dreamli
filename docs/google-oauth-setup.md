# Google OAuth setup for Dreamli (NextAuth)

This guide walks you through configuring Google OAuth in Google Cloud Console and wiring it up to this project (Next.js + NextAuth v5). It covers local development, production, and troubleshooting.

If you just need the values to paste, see the quick reference at the end.

---

## 1) Prerequisites
- A Google account with access to [Google Cloud Console](https://console.cloud.google.com/).
- Your deployment domain(s), for example:
  - Local: http://localhost:3000
  - Production: https://your-domain.com
  - (Optional) Staging: https://staging.your-domain.com

In this repository, Google login is handled by NextAuth using the built-in Google provider. The callback path is fixed at:

- /api/auth/callback/google

So your full callback is, for example: https://your-domain.com/api/auth/callback/google

The core NextAuth route is already implemented at: app/api/auth/[...nextauth]/route.ts (re-exporting handlers from lib/auth.ts).

---

## 2) Create a project (or select existing)
1. Go to Google Cloud Console → Select your project (or create a new one).
2. Ensure the project is active in the top navigation bar.

---

## 3) Configure the OAuth consent screen
1. Navigation: APIs & Services → OAuth consent screen.
2. User Type:
   - Internal: Only users within your Google Workspace domain can log in.
   - External: Anyone with a Google account can log in (typically what you want for consumer apps).
3. App information:
   - App name: Your app name (shown on Google consent page).
   - User support email: Your contact email.
   - App logo: Optional but recommended.
4. App domain (recommended for production):
   - Application home page: https://your-domain.com
   - Privacy policy: https://your-domain.com/privacy (provide a real page)
   - Terms of service: https://your-domain.com/terms (provide a real page)
   - Domain verification: If you fill these, Google may require you to verify the domain under Search Console.
5. Authorized domains: Add your-domain.com (and staging domain if used). Do not include protocol or path, just the domain.
6. Scopes: For standard sign-in, you only need the default OpenID scopes (email, profile). No sensitive or restricted scopes are necessary.
7. Test users (while app in Testing): If your consent screen status is Testing (not Published), add the Google accounts that should be allowed to sign in. In Production (Published), this is not required for public access.
8. Save and Continue until Done.

---

## 4) Create OAuth client credentials (Web application)
1. Navigation: APIs & Services → Credentials → Create Credentials → OAuth client ID.
2. Application type: Web application.
3. Name: e.g., Dreamli Web Client.
4. Authorized JavaScript origins (origins where your browser app is served):
   - Local: http://localhost:3000
   - Production: https://your-domain.com
   - Staging (if any): https://staging.your-domain.com
5. Authorized redirect URIs (exact redirect callback URLs):
   - Local: http://localhost:3000/api/auth/callback/google
   - Production: https://your-domain.com/api/auth/callback/google
   - Staging (if any): https://staging.your-domain.com/api/auth/callback/google
6. Click Create → copy the Client ID and Client Secret.

You can always edit these lists later to add more domains/environments.

---

## 5) Add credentials to this project
Add the values to your environment variables. For development, use .env.local. For production, set them in your hosting provider’s environment settings.

Required variables:
- NEXTAUTH_URL
  - Local: http://localhost:3000
  - Production: https://your-domain.com
- NEXTAUTH_SECRET
  - A strong random secret, e.g., generated by `openssl rand -base64 32`
- GOOGLE_CLIENT_ID
  - From the OAuth client you created
- GOOGLE_CLIENT_SECRET
  - From the OAuth client you created

Example .env.local (development):

```
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=replace-with-a-strong-random-string
GOOGLE_CLIENT_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Note: This repo already uses these variables in lib/auth.ts via the NextAuth Google provider.

## 6) How the flow works in this app
- Frontend triggers signIn("google") (see app/(lang)/[lang]/auth/LoginForm.tsx and RegisterForm.tsx).
- NextAuth handles the OAuth redirect: your-site → Google → back to /api/auth/callback/google.
- On first sign-in, the Prisma adapter creates a user. A signup bonus is awarded in the createUser event.
- After login, the user is redirected to a callbackUrl computed in the UI (e.g., /en/auth/account or a provided redirect param).

---

## 7) Publishing and verification tips
- If you only request basic profile (email, profile, openid) and do not use sensitive/restricted scopes, you usually do not need a long verification process.
- If you add sensitive scopes later (e.g., Gmail API), you may need to undergo Google verification.
- In Testing status, only Test users can log in. To let the public log in, click "Publish App" on the consent screen.
- If you configure app domain links (privacy policy, terms), you may need to verify your domain.

---

## 8) Common errors and fixes
- Error 400: redirect_uri_mismatch
  - Ensure the callback URL exactly matches one you added under Authorized redirect URIs, including protocol and path, e.g., https://your-domain.com/api/auth/callback/google
- Error: disallowed_useragent or similar in embedded browsers
  - Test in a standard browser window; some embedded webviews are not supported by Google OAuth.
- Stuck on consent screen or forbidden for non-test users
  - Publish the consent screen (or add the account as a Test user while in Testing).
- Wrong host in development
  - When using tunnels (e.g., ngrok), add that temporary domain to both JavaScript origins and redirect URIs for the session.
- NEXTAUTH_URL mismatch
  - Ensure NEXTAUTH_URL reflects the actual origin you’re using (http://localhost:3000 for dev, your https domain for prod).
